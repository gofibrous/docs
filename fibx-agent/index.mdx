title: "What is FibX?"
description: "A command-line tool and agent skill framework for executing DeFi operations across multiple chains, powered by Fibrous aggregation."
---

FibX is a CLI-based DeFi execution layer that enables both developers and AI agents to perform on-chain operations — token swaps, transfers, balance checks, cross-chain portfolio inspection, and Aave V3 position management — across **Base, Citrea, HyperEVM, and Monad**.

It combines [Fibrous](https://fibrous.finance) aggregation for optimal swap routing with flexible wallet authentication — use your own private key directly, or create a server-managed wallet via [Privy](https://privy.io).

## How It Works

FibX operates as a CLI tool (`npx fibx@latest`) that communicates with the Fibrous aggregation stack and, when needed, a backend server for Privy-managed wallet operations. Writes are preflighted against the chain before broadcast, so predictable failures surface as errors rather than spent gas.

```mermaid
flowchart LR
    A[User or AI Agent] --> B[fibx CLI]
    B --> C[Private Key Wallet]
    B --> D[fibx-server]
    D --> E[Privy Server Wallets]
    C --> F[Fibrous Aggregation API]
    D --> F
    F --> G[Blockchain]
```

## Security Model

FibX moves real funds, so the limits that matter are enforced below the agent —
not in a prompt that a jailbreak could rewrite.

<CardGroup cols={2}>
  <Card title="Limits live below the prompt" icon="shield-halved">
    Privy server wallets are created with a signing policy attached. Privy evaluates it on every signing request: transactions are allowed only for the chains FibX serves, each under a per-transaction native value cap, and the generated rule set denies private key export. A jailbroken prompt cannot raise these — they are not instructions the model can rewrite.
  </Card>
  <Card title="Preview before value moves" icon="hand">
    Transactional MCP tools advertise `destructiveHint: true`, which clients may use to prompt for confirmation. All of them accept `simulate=true` for a no-broadcast preview; gas estimates are returned where they can be computed without sending anything first.
  </Card>
  <Card title="Keys never reach the client" icon="key">
    In Privy mode the private key stays in Privy's TEE and the CLI only ever receives a signature. In private-key mode the key is encrypted at rest with AES-256-GCM and never leaves your machine.
  </Card>
  <Card title="Preflighted before broadcast" icon="flask">
    Writes are preflighted against the chain before they are sent, so failures surface as readable errors instead of burned gas.
  </Card>
</CardGroup>

<Note>
  The policy is defense in depth on the normal signing path, not a containment
  guarantee. The Privy app credentials authorize both signing and policy
  administration, so the backend that holds them is the administrative trust
  boundary.
</Note>

## Typical Workflow

Every FibX session follows the same four-step pattern:

<Steps>
  <Step title="Authenticate">
    Import your private key for direct usage, or log in via email OTP to create a Privy server wallet. Either method creates a session that persists across commands.
  </Step>
  <Step title="Check Funds">
    Query native and ERC-20 token balances on the target chain, or inspect the full cross-chain portfolio with USD valuations.
  </Step>
  <Step title="Execute">
    Perform a swap, transfer, or Aave operation. The CLI preflights the write before submitting it on-chain, and `--simulate` returns a preview without broadcasting anything.
  </Step>
  <Step title="Verify">
    Check the transaction status and obtain the block explorer link.
  </Step>
</Steps>

## Quick Example

```bash
# Check a price first — no wallet, no login required
npx fibx@latest quote 0.01 ETH USDC

# Authenticate with your private key
npx fibx@latest auth import

# Check balance on Base
npx fibx@latest balance

# View your cross-chain portfolio
npx fibx@latest portfolio

# Swap 0.1 ETH for USDC
npx fibx@latest trade 0.1 ETH USDC

# Verify the transaction
npx fibx@latest tx-status 0xabc...def
```

## Two Ways to Use FibX

<Tabs>
  <Tab title="As a CLI Tool">
    Run commands directly in your terminal. Ideal for developers who want programmatic access to DeFi operations or need to script workflows.

    ```bash
    npx fibx@latest portfolio --json
    npx fibx@latest trade 0.05 ETH USDC --chain base --simulate
    ```
  </Tab>
  <Tab title="As Agent Skills">
    Import the [fibx-skills](https://github.com/Fibrous-Finance/fibx-skills) into your AI agent's skill registry. The agent interprets natural language prompts and maps them to the appropriate CLI commands.

    | User Prompt                      | Skill Triggered       |
    | -------------------------------- | --------------------- |
    | "How much USDC for 0.1 ETH?"    | `quote`               |
    | "What's my wallet address?"      | `wallet-info`         |
    | "Swap 0.05 ETH to USDC"         | `trade`               |
    | "Check my balance on Monad"      | `balance`             |
    | "Show me my portfolio"           | `portfolio`           |
    | "Send 10 USDC to 0x123..."      | `send`                |
    | "Supply 100 USDC to Aave"       | `aave`                |
    | "I'm getting rate limit errors"  | `config`              |
  </Tab>
</Tabs>

## Telegram Bot

[fibx-telegram-bot](https://github.com/Fibrous-Finance/fibx-telegram-bot) puts the
same execution layer in a chat window. It drives the FibX MCP server, so it has
exactly the tools described here — quotes, swaps, transfers, portfolio and Aave —
reached through natural language instead of flags.

- **Bring your own model.** Choose OpenAI, Claude or Gemini and supply your own
  API key. There is no shared key and no centralized inference billing; keys are
  encrypted at rest and can be erased with `/deletekey`.
- **Isolated per user.** Every user gets a dedicated MCP process under its own
  virtual HOME, so the application routes sessions, config and caches to separate directories. These processes share the bot host's OS account, so this is application-level separation rather than an OS or container boundary.
- **Price alerts.** `/alert ETH above 4000` notifies you once when the price is
  reached — no login or AI key required.
