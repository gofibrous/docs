## Requirements

- **Node.js** v18 or higher
- **npm** (included with Node.js)
- A running [fibx-server](https://github.com/Fibrous-Finance/fibx-server) instance only if you use Privy-managed wallet operations

<Note>
  No global installation is needed. All commands use `npx fibx@latest`, which always fetches the latest version (currently **v0.8.2**).
</Note>

## Installation Options

Run FibX directly with `npx`:

```bash
npx fibx@latest status
```

Or install it globally:

```bash
npm install -g fibx
```

## Installing Agent Skills

To add fibx skills to your AI agent, use the Vercel Skills CLI:

```bash
npx skills add Fibrous-Finance/fibx-skills
```

This installs the pre-built skill definitions from the [fibx-skills repository](https://github.com/Fibrous-Finance/fibx-skills) into your agent's skill registry. No separate installation of `fibx` is needed — all skills execute via `npx fibx@latest`.

## Verify Your Environment

```bash
node --version   # Must be v18.0.0 or higher
npm --version
```

## Try It Without a Wallet

Before setting anything up, you can check live prices — `quote` needs no session,
wallet, or keys:

```bash
npx fibx@latest quote 0.01 ETH USDC
npx fibx@latest quote 1 MON USDC --chain monad
```

## Authentication

Commands that inspect or act on a wallet — including `address`, `wallets`,
`balance`, `portfolio`, `send`, `trade`, `aave status`, and Aave actions — need
an active session. Public or local commands such as `quote`, `status`,
`tx-status`, `config`, and `aave markets` can run without one. Two
authentication methods are available:

### Private Key Import (Recommended)

If you already have a wallet with a private key, this is the fastest way to get started. The key is encrypted and stored in a local session file for the duration of the session. This mode does not require `fibx-server`.

<Warning>
  Your private key will be stored locally in an encrypted session file. Only use this method on a trusted device.
</Warning>

```bash
# Interactive prompt — paste your private key when asked
npx fibx@latest auth import

# Confirm the session is active
npx fibx@latest status
```

This is ideal for developers and agents that already manage their own wallets. The imported key is used directly for signing transactions — no external server holds your key.

### Email OTP (Alternative — Privy Server Wallets)

If you do not have a private key or prefer a managed wallet, you can
authenticate via email OTP. This creates a server-managed wallet through
[Privy](https://privy.io). Signing is requested through `fibx-server`, and the
private key itself is not returned to the CLI. This mode requires `fibx-server`
to be running and reachable.

```bash
# Step 1: Request an OTP code
npx fibx@latest auth login user@example.com

# Step 2: Enter the code received via email
npx fibx@latest auth verify user@example.com 123456

# Step 3: Confirm the session is active
npx fibx@latest status
```

### Session Management

```bash
# Check current session status
npx fibx@latest status

# Get the active wallet address
npx fibx@latest address

# End the session
npx fibx@latest auth logout
```

## Common Command Options

These flags are available where shown in the command reference:

| Flag                | Description                                     | Default |
| ------------------- | ----------------------------------------------- | ------- |
| `-c, --chain`       | Target chain: `base`, `citrea`, `hyperevm`, `monad` | `base`  |
| `--json`            | Output results as JSON (useful for scripting)   | `false` |
| `--simulate`        | Command-specific preview; behavior varies by command (see below) | `false` |

### Chain Selection

Commands that accept `--chain` default to **Base** unless their reference says
otherwise.

```bash
# Explicit chain selection
npx fibx@latest balance --chain citrea
npx fibx@latest trade 1 MON USDC --chain monad

# Default: Base
npx fibx@latest balance
```

## First Transaction

After authenticating, run through a complete workflow to verify everything is working:

<Steps>
  <Step title="Check your balance">
    ```bash
    npx fibx@latest balance
    ```
  </Step>
  <Step title="Execute a swap">
    ```bash
    npx fibx@latest trade 0.001 ETH USDC
    ```
    The CLI finds a route via Fibrous, handles any required token approval, estimates the swap where supported, and submits it.
  </Step>
  <Step title="Verify the transaction">
    ```bash
    npx fibx@latest tx-status <transaction-hash>
    ```
    This returns the on-chain status, gas used, and a block explorer link.
  </Step>
</Steps>

## Preview Behavior

`send --simulate`, `trade --simulate`, and Aave actions with `--simulate` return
a no-broadcast preview. Review the result and the command-specific limitations
before submitting the live operation.

```bash
npx fibx@latest send 0.1 0xRecipient --simulate
npx fibx@latest trade 0.1 ETH USDC --simulate
npx fibx@latest aave supply 1 ETH --simulate
```

<Note>
  Preview output varies by path. If an ERC-20 trade needs approval,
  `trade --simulate` reports `requiresApproval: true` without submitting the
  approval or returning a gas estimate. An Aave preview returns the normalized
  request only; it does not perform on-chain validation or estimate gas. Preview
  success does not guarantee that later execution will succeed.
</Note>
